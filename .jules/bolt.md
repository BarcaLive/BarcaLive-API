## 2024-05-18 - Optimize cleanName string replacements
**Learning:** Moving inline regular expressions out of a frequently called function (like `cleanName`) and into a global array prevents the runtime (like V8) from constantly recompiling and reallocating RegExp objects on every function call. Furthermore, V8s internal `String.prototype.replace()` natively performs a fast scan first, so manually wrapping it in a `RegExp.prototype.test()` actually causes the engine to scan the string twice when a match is found, counteracting the intended performance micro-optimization.
**Action:** When optimizing repeated string replacements with regexes, extract the literal expressions outside the hot path scope, and trust the engines native `.replace()` to handle no-match fast paths efficiently.
