## 2024-05-24 - Cache Busting via Dynamic Time Strings
**Learning:** Using `Date.now()` or `new Date().toISOString()` directly in API request URLs inside a Cloudflare Worker environment completely invalidates the cache layer (e.g., `fetchCached`). Because the timestamp advances every second, the URL (which acts as the cache key) constantly changes, forcing a cache miss. This effectively renders configured TTLs (120s, 300s) useless and bypasses caching altogether.
**Action:** When querying APIs using time-based parameters (`startTime[after]`, `startTime[before]`) combined with caching, always round down the current timestamp to match the cache's TTL using modulo arithmetic (e.g., `now - (now % 300000)`). This ensures the generated URL remains static for the duration of the TTL, yielding stable cache keys and actual cache hits.
